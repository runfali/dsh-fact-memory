# dsh-fact-memory

[English](README.md) | 简体中文

给 [DeepSeek Harness](https://github.com/deepseek-ai) 的跨会话事实记忆：一个 SQLite 权威事实库、三个工具，以及一段随每次请求注入的预算内目录。

> [!IMPORTANT]
> **记的是事实，不是文档。** 一条记忆 = 主体 + 属性 + 值 + 证据等级 + 时间。用户亲口说的话高于模型推断；模型猜出来的值永远不会悄悄覆盖用户说过的值，它只会变成一条可见的冲突。
>
> **记忆是历史证据，不是指令。** 常驻目录只告诉模型「库里有什么」，从不告诉它该做什么。每条召回都带日期，时间敏感的判断必须用现场工具核实，任何记忆都不构成授权。
>
> **记错比没记更糟。** 所以自动捕获默认关闭、形似凭据的内容直接拒写、个人隐私入库但不对模型可见、遗忘会留下墓碑阻止同样的内容被重新写回。后两条是默认值而不是铁律：`refuseCredentials` 关掉后凭据会作为敏感事实留下（仍不进模型上下文），`sensitiveModelVisible` 打开后敏感事实才进入目录与检索结果——按需取舍，默认仍在安全一侧。

## 为什么需要它

每个会话都从零开始。上周说过的偏好、上次任务里定下的端口、项目已经约定的规范——只要不塞进每一次提示词，下个会话就消失了。

常见的三种绕道各有各的失败方式：超大的人设提示词会无限膨胀且无法维护；文档知识库回答的是「文档里怎么写的」，不是「用户跟我说过什么」；把历史会话压缩成摘要则有损，而且越长越糊。

这个插件改用一个小的、结构化的、可检查的库：

| 做法 | 为什么不行 |
| --- | --- |
| 人设提示词 | 每次请求都为每条事实付费；改一条事实等于重写一段话 |
| 文档知识库 | 事实按「主体 + 属性」定位，不按文档相似度 |
| 会话摘要 | 有损、无界，模型无法引用具体那条断言 |
| **本插件** | 结构化槽位、预算内召回、证据与时间都保留 |

| 对话内的三个触点 | 回合尾的「本轮记忆」卡片（写入几条、待审几条、待裁决几条，带「查看」）、右栏的「记忆详情」抽屉（列出这个会话写入的事实）、会话列表行上的记忆小标记。计数落在库里，宿主重启后仍在；工具在某轮写下的也会挂到该会话上，即使这一轮没有抽取摘要，卡片也能从这些带锚点的事实里得出计数。自动抽取是异步的，卡片会一直问到这个会话的抽取有结论（写完或确认没写）为止，慢模型不再表现为「永远没有卡片」。 |
| 设置卡 | 摘要性质，具体工作在页面里做（待审提案只在页面里，设置卡不重复列）：日常配置项的输入控件，底部还有一组默认折叠的「高级设置」（预算、超时、时区、备份轮转、自动查重这类调优项都收在里面）、实时计数、一跳图谱预览，以及未裁决的冲突（每边的日期与证据等级），可以直接在这里裁决，不必回到对话里再陈述。按钮：导出、重建索引、重建向量（配置了向量模型才出现）、查找近重复、跑体检，以及「一键清空」（清空事实/实体/提案/冲突/向量索引，保留配置项与抽取运行记录，清空前自动备份，需二次确认） |

工具回执是一个封闭集合：`ok`、`saved`、`pending`、`needs_selection`、`not_found`、`refused`、`conflict`、`unavailable`。空结果的含义是「库里没有记录」，绝不是「该说法为假」。

## 工作原理

**存储。** 一个 SQLite 库，走宿主内置的 `node:sqlite`——不编译原生模块、不起旁路服务。WAL、外键开启、`synchronous=FULL`、嵌套事务用 SAVEPOINT。每次提交写入都会推进 generation，设置卡据此显示库确实变了。

**槽位与断言。** 一条事实是 `(主体, 属性, 作用域, 限定条件, 值)` 加证据。断言键是对规范化后的主体、属性、限定条件与值做 SHA-256。部分唯一索引保证「单值槽位只有一个当前值」，多值槽位自然累积。

**证据与替换。** 证据等级 `explicit_user`（用户原话）> `confirmed_user`（采纳提案时写入）> `observed`（模型读出）> `unverified`。可信的新值会双时态替换旧行（写 `valid_to`，旧行 `superseded_by` 指向新行）；不可信的反驳则两行都保留，新行标 `conflict` 并入冲突组，`memory_search` 回 `needs_selection` —— 明确告诉模型两边都不能当定论。用户后来自己给出答案时，槽位会落定：对手行退役、冲突组关闭，只剩一个当前值。设置卡会列出未裁决的冲突（每边的日期与证据等级），用户可以直接点选裁决，不必回到对话里再陈述一次。

**写入前查重与同义合并。** 同一句话常常从三条路径进来——规则匹配、模型抽取、显式 `memory_write`——措辞略有不同，放任不管，图谱很快会被近重复节点填满。写入前先做两级拦截：主体名先归一（折叠大小写与分隔符，去掉「插件/项目/服务/系统/模块/平台/工具」这类角色后缀，所以 `DSH Fact Memory`、`dsh-fact-memory`、`dsh-fact-memory插件` 是同一个主体），断言键完全相同的写入直接判重；否则用 IDF 加权余弦做近似判重，阈值 0.72，并要求至少 3 个共享词元（短文本的余弦不稳）。关键的一条是**稀有词元否决**：两侧词面几乎一致、但只有一边出现某个稀有标识符（`7801` 与 `7802`、`bge-m3` 与 `bge-large`）时，无论余弦多高都不合并——按 Fellegi-Sunter 的思路，单边稀有词元是「不同」的强证据。否决只看标识符形状的 ASCII 词元，两个中文二元组之间的差异正是余弦该处理的部分。语料少于 12 条时 IDF 没有意义，近似判重整体关闭，只留完全相同这一级。

**近重复复核。** 写入前的查重只看「正要写的那条」，库里已经存在的两种说法会一直并存。后台复核补这一段：候选取「词法档位」与「向量」的并集（余弦 ≥ `consolidateCosineFloor`，默认 0.85）——词法腿保住标识符差异（187/188 这种向量会被抹平的），向量腿抓换说法（词法看不见的）。只在同一主体、同一 scope 内比，敏感事实在 SQL 层就被排除，原文不会发给模型。模型只回答一个封闭问题（同一件事 / 不同 / 拿不准），既看不到事实 id，也不决定保留哪条；保留哪条由规则定（证据等级、更早的观察、id 定序），所以同一对永远出同一条提案。「不同」的结论按向量代际记住，一对只花一次调用，而不是每轮都问。一轮最多花 `consolidateMaxPairs` 次调用，并且按主体轮转——否则每晚写一行的备份主体会把整轮预算吃光；设置卡上的按钮会把预算放大三倍强制跑一轮。任何结论都不自动落库：判「同一件事」或「拿不准」只写一条 `merge` 提案，采纳后败者变 `superseded`，来源证据搬到保留的那条。

**什么时候跑。** 这个复核是插件自带的：不需要 cron、不需要 Windows 计划任务、不需要 dsh 的定时任务，也没有「记得去点一下」这回事。插件加载 2 分钟后启动计时器（向量补扫是 15 秒开始，还没有向量的行只会把词法腿已经知道的事再说一遍），之后每分钟看一次表，距上次满 `consolidateIntervalMs` 就跑一轮。有两点要先知道：它只在 DSH 运行时跑；计时器在内存里，重启即归零，所以每次启动后约 2 分钟会跑一轮，而不是接着等剩下的时间。开销仍受上面两条约束——一轮最多 `consolidateMaxPairs` 次调用，同一对在每个向量代际只判一次，所以库没有变化时一轮根本不调模型。没有可用模型时候选挂起记 `deferred`，不写任何东西；没有向量模型时只剩词法腿，抓不到换说法。要关掉：`consolidateIntervalMs: 0` 只保留按钮和接口两个入口，`autoConsolidate: false` 彻底关闭；设置卡的按钮（或 `POST /api/fact-memory/consolidate` 带 `{force:true}`）会立刻跑一轮，预算放大三倍。

**只退休，不删除。** 新的可信值取代旧值时，旧行不会被删掉：它被打上 `superseded`、用 `superseded_by` 指向取代者，`valid_to` 就是新值到达的那一刻。这个双时态正是关键——「端口在周二之前是 7801」仍然问得出来，导出里也还看得见上个月库相信的是什么。整个插件只有 `memory_forget` 和明确的「一键清空」会删事实，两者都是人主动要求的。

**流水账会被折叠。** 每晚跑一次的备份、每天一次的自检、每周的巡检：它们**报出来的结果**同主体、同属性，只有日期不同（说的是这类事实的内容，不是插件自己会去跑定时任务）。每晚一行会把别的记忆全埋进流水账里，所以当一条写入除「恰好一个日历日期」之外与库里的值一致时，不再新建行，而是就地更新那一行（值、观察时间、来源清单），并把 `folded_count` 加一、把最近 20 个旧值留在 `folded_from` 里。槽位允许多少个值不影响折叠：多值槽位里同一条流水账同样只留一行——两句话是不是同一句话，与这个槽位能存几个值无关。护栏是故意收紧的：值里必须**恰好一个**可解析日期、且其余至少还有 4 个字符，所以 `187`/`188`、`port 7801`/`port 7802`、`from 20260101 to 20260201` 永远不会互相折叠。检索结果仍然打印日期与折叠次数，折叠过的行不会丢掉历史。

**同一个槽位里新的在前。** 主体、属性、限定符都相同的行属于同一个槽位。不管词法分数如何，槽位一律按观察时间从新到旧渲染，并锚定在该槽位最高分成员原本的位置上，所以两个月前的旧说法不会压过取代它的那条。旧行不会被丢掉：它们排在下面，「以前是什么」照样答得出来。

**体检器。** 每六小时插件给自己做一次体检，找三种写入时关卡看不见的形态：一条只把自己的属性复述一遍的事实（「以错误信息失败」这种人写的那种）、因为日期长在属性名里而折叠不到的流水账、以及同一主体被拼成两个实体。每一类只生成**一条聚合提案**——明细列在提案里，单条上限 50 项（更长的会另起一批，标题带 n/m）——所以库里有两百行过期数据，也只问你**一次**，不是两百次。采纳后才会动库：把自我复述的行退休、把流水账并进最新那行、把碎片实体并入正规实体；不采纳什么都不会变。这里的折叠同样计数：幸存行会记下吸收了几次运行，读起来和写入时折叠一样是「共 7 次」。一张卡也是逐行判、不是全有全无：如果某行在体检之后被改过，只跳过那一行（回执里写明 `skippedStale`），同批其余照常执行；而如果一行都没落地，卡片会明确拒绝，不会假装成功。批次里的单条明细还能在采纳前剔除（`proposal-prune`），一条误判不至于让你把整张卡否掉。页面还会给出「自你上次查看后新增 N 条」的摘要，于是「待审 38 条」变成「周二以来新增 12 条」。

**页面的行编辑是有栅栏的。** 所有会改动或退役既有行的路由——`rebuild`、`wipe`、`resolve`、`fact-update`、`fact-expire`、`fact-restore`、`proposal-apply`、`proposal-reject`、`proposal-revise`、`proposal-prune`、`import`——都接受 `expectedGeneration` 与 `operationId`。触发型路由（`audit`、`consolidate`、`index-vectors`、`calibrate`、`extract`、`key`、`review-seen`）不接受：它们产出的是提案、派生状态或一份凭据，不会覆盖页面正拿着的那一行。generation 是前置条件：如果页面开着的时候别的会话改了库，写入会被拒绝并返回 `stale: true` 和最新 generation，页面刷新而不是覆盖更新的真相。operationId 让连点两次只写一次——同 id 同内容返回第一次回执（`replayed: true`）且不推进 generation，同 id 不同内容按冲突拒绝。被拒绝的写入会删掉自己的操作行，所以诚实的重试不会被误判成重放。

**遗忘。** `memory_forget` 把行标为 forgotten、从全文索引移除，并写两条墓碑：一条按断言、一条按证据。此后同内容的写入或导入会在建行之前被拒绝。墓碑刻意全局生效：用户忘掉的东西不能从另一条路径复活。

**检索。** FTS5 BM25（中文二元切分 + ASCII 词元），加一条精确标识符通道（路径、URL、版本、端口、包名），用倒数排名融合（`k=60`）。敏感事实与 `model_use_allowed = 0` 的事实永远不进入面向模型的召回。

**交换。** `export` 写一行清单 + 每事实一行：UTF-8 无 BOM、LF 行尾、原子改名，`records_sha256` 覆盖事实行。`import` 先预览（`new` / `duplicate` / `conflict` / `tombstoned` / `invalid`），返回绑定「文件哈希 + 库 id + generation」的 token；用过期 token 提交会被整体拒绝，绝不半途应用。导入的事实降级为 `observed`，敏感项强制 `model_use_allowed = 0`。预览判为 `conflict` 的记录在明确要求时可以应用，代价是进冲突队列——导入表达的是「文件里这么写」，不是「用户确认过」。导出与导入路径限定在数据目录内，UNC 路径直接拒绝；若通过域名访问远程 GUI，需要在 `DSH_FACT_MEMORY_ALLOWED_HOSTS` 里列出该主机名（回环地址与私有 IP 字面量无需配置）。

**提案制。** 有些改动不该自动落库：推断值、置信度低于 60% 的值、归并、别名。它们进 `proposals` 表，每条带动作、目标事实及其 record revision、以及证据。采纳不是重放而是重新校验：先比对目标 revision，目标已改、已消失或已遗忘就让提案 `stale`，而不是覆盖更新的真相。提案有稳定的指纹与版本号，同一改动重复提出会返回已有行而不是堆重复记录；在卡里改值会生成新版本并在应用前重新校验。采纳写入 `confirmed_user` 证据，并**重新**做隐私扫描，因此采纳一条提案不能把敏感数据洗成模型可见。

**语义检索。** 两条可选通道，都指向你自己配置的端点：向量（`POST <base>/embeddings`）与重排（`POST <base>/rerank`）。向量带指纹（提供方、基址、模型、维度、归一化、输入模板），只有与当前指纹一致的向量参与召回——换模型后旧向量自然退出候选，BM25 继续工作。重建向量不是「记得去按按钮」的事：配置了向量模型后，每隔 `vectorIndexIntervalMs`（默认 10 分钟；`0` 只保留手动）自动为新增或改动的事实补建，一轮抽取写入新事实后也会立刻补扫一次；一键清空连同向量表一起清掉，不会留下描述旧库的向量。重排分数按声明的 `scoreMode`（0–1 / logit / native）校验，超出声明范围会让整次重排作废，而不是悄悄改排序。重排只在有校准记录时才用于过滤：至少 20 条相关 + 20 条不相关、precision ≥ 95%、recall ≥ 80%；没有校准就只排序，工具会回 `rerank_uncalibrated`，且不把任何结果当定论。整次检索有预算（总 2500ms、查询向量 800ms、重排 1500ms、候选池 20 条并预留至多 5 个精确标识符位）；超时或失败降级到词面通道，并在 `paths` 里写明。

**自动抽取。** 抽取有一条便宜的路（`autoCapture` 的规则匹配）和一条贵但更准的路（模型）。模型那条默认关闭，触发点是 `turn/end`——**一轮结束**，无论这一轮以文本、纯工具调用还是中断收尾。

两条路不会对同一段文本同时开工。当模型那条会读到这条消息时，规则这条保持沉默，把整条消息交给模型（否则同一句话会被各写一条）；模型随后抽到的同一条由 claim key 折进原来那条记录。只有「记住 / 记一下」这种显式请求仍然立刻写，不等模型；模型没配好、或这一轮不在模型路径上时，规则这条照旧兜底。压缩与标题代理发来的会话 transcript（以 `USER:` / `ASSISTANT:` 开头）两条路都直接拒绝——那是代理转述的对话，不是用户说的话，从里面抽出来的「事实」全是助手自己的措辞。委派出去的子智能体会话同样排除：它的会话头带 `origin: "subagent"`（或正的 `delegationDepth`），里面的对话是任务脚手架而不是用户定下来的长期事实，父会话保持唯一写入方。只有父级明确要求「记住」时，子智能体仍可显式调用 `memory_write`。

它在后台跑，不占对话：事件处理器只把任务排进队列就返回，模型调用与写库都在之后发生。队列按会话隔离：**同一会话严格 FIFO 串行**（上一轮没跑完，下一轮排队而不是插队或取消），**跨会话并行**。每次 pass 处理的是一个固定快照——触发它的那条 `turn/end` 的 seq 就是这次范围的右边界，因此之后才出现的轮次不会被这次 pass 顺手吃掉；快照的起止 seq、消息数、字符数与文本哈希都会写进 `lastRun.snapshot`，便于回查「这次到底处理了哪一段」。

信号词（中英文的显式记忆请求、长期约定与偏好、定下来的变更，以及「端口/路径/版本 = 值」这种配置绑定）是快速通道，不是唯一通道：没信号的文本不会被丢掉，游标停在原地，连续 `extractFallbackTurns`（默认 3）轮、或累计到 `extractFallbackChars`（默认 800）字之后，模型照样读一遍——「我们跑在 8123 上」不会因为少了暗号就永远消失。没信号时先记一条「已跳过」的决策；轮数用完的那次 pass 会绕过词表直接问模型。手动动作不受词表约束：队列页的「重试抽取」和粘贴抽取都直接问模型——按钮按下去之后，就不该再被信号词挡回来。有信号时发这一轮**新增的对话文本**：用户原话和助手的回复都会读（用户多半在安排活，事实常藏在助手查完、改完的回复里；`extractIncludeAssistant` 默认开启，关掉就只读用户原话），工具输出、注入的提醒、压缩代理转述的 transcript 都不在内——并要求每条候选给出逐字引用；引用在原文里找不到的直接丢弃，不当成「部分成功」。候选还要过一遍形态闸门：主体必须是稳定主体名，句子片段、疑问句、请求、对话里的元信息（「上面」「结论先说」「用户」「助手」之类）一律拒绝——两条路径共用同一套判定，所以它们不会对「什么算一条事实」产生分歧。模型只拿到文本：没有工具、没有会话历史、没有写库权限；置信度低于门槛（默认 0.6）的进提案队列。失败重试 1/5/30 分钟，三次都失败就把原文连同来源锚点持久化成 Pending 项并推进游标（不推进会重复消费同一段）。长文本切成多段，一次处理其中若干段（`extractChunksPerPass`，默认 2），未处理的部分游标停在它前面。写入之前先合并各段：去重是本地零成本完成的，只有出现重复或同一属性两个值时才额外调一次模型糅合——模型只能重排给定候选，逐字段核对，越界即整份作废。思考默认关闭（`extractThinking`）：抽取是机械活，推理只会吃掉输出预算。

一个已知边界：一次性 CLI 会话可能在延迟窗口内就退出了。这种场景把 `extractDelayMs` 设为 `0`；常驻的桌面/网页宿主没有这个问题，agent 释放时也会把待跑的那次 flush 掉。

**图谱。** 图谱是投影，绝不是第二权威源：边由「以另一个实体为值」的事实派生，每条边带支撑事实的 id。只有 active 与 scheduled 的事实产生当前边，所以遗忘或替换事实会在同一事务里让边消失或退役。页面给两个视图：**星云**（默认，三维 WebGL）把实体与值合成一个节点集，按度数聚团，三层画布——星空底、辉光节点、2D 标签；预算 600 节点 / 1200 边，超出会如实报出未展示的条数，实体最多 300 个，免得一个胖实体吃掉整个预算；**一跳邻域**（100 节点 / 200 边）用来读关系。有争议的关系只在「全部」视图出现并打标，绝不显示为已确认。悬停看邻居，点开节点或边会列出支撑事实，这就是「从边回查原话」的路径；每次打开图谱页签都会重新读取投影，页面从不拿缓存冒充当前库，工具条上另有手动刷新按钮；WebGL 不可用时自动降级为 SVG 树，而不是白屏。

## 环境要求

- dsh `>= 0.2.2-rc.1`（包的 `compatibility` 字段同时限定 `< 0.3.0-0`）
- Node `>= 22.13`（宿主自带运行时即可；`node:sqlite` 需带 FTS5）

无原生模块、无需编译。插件自己不发起网络请求，除非你配置了向量、重排或抽取端点——默认配置下（各通道都是 none、`llmSource: host`）没有任何东西离开这台机器。

## 安装

```bash
cd dsh-fact-memory
npm install                     # 唯一运行时依赖：@deepseek-ai/schemastery
dsh plugin --profile web add /absolute/path/to/dsh-fact-memory
```

包里带一份 bundle patch（`cordis.patch.yml`），插入一行：

```yaml
- insert:
    - id: dsh-fact-memory
      name: 'dsh-fact-memory'
      config:
        dataDir: ''
        injectDirectory: true
        directoryBudget: 800
        injectReminder: true
        autoCapture: false
        searchLimit: 5
        backupBeforeExport: true
```

这一行必须是 **插入**（如上）。光写 `- id: dsh-fact-memory` 是对已存在条目的「覆盖」，宿主会报 `patch: entry "dsh-fact-memory" not found`。

安装后重启宿主一次：bundle patch 只在启动时读取。

## 配置

| `dreamBackfillMaxSessions` | `50` | 一次手动历史回填最多读多少个旧会话（新的优先），已采集的会话跳过。 |
| `dreamBackfillMaxChars` | `200000` | 一次手动历史回填最多往待整理队列里拷多少字符。 |

> 自定义抽取端点按「OpenAI 兼容」但容错读取：`choices[].message.content`（字符串，或 `{type:"text",text}` 数组）、`choices[].text`、Responses 的 `output_text` / `output[]`，以及 JSON 正文后面被网关追加了 `data: [DONE]` 的情况都能取出文本。200 却没有正文时，报错会带上原因（`finish_reason=length`、只有 `reasoning_content`、或端点返回的 `error`），不再统一说 "no text"。请求侧也按档降级：关闭思考会一次带上三种写法（`chat_template_kwargs.enable_thinking`、`enable_thinking`、`reasoning_effort`），端点拒哪一种就收窄到它接受的最小写法并记住；`response_format`、`max_completion_tokens` 同样自动退让。有一种失败不是配置错：某些模型的思考长度随输出预算线性增长，调大 `maxTokens` 只会买来更多思考、正文永远为空——这时报错直接写明「预算全被 reasoning_content 吃掉」，并建议在网关侧关掉思考，而不是无济于事地加预算；只有「答案确实被截断」才会自动翻倍一次（上限 8192）。抽取失败的那一次运行、以及挂起列表里的每一行，队列页都有「重试抽取」按钮：用当初的原文按当前配置再读一遍，点一次等于一次模型调用。

## 梦层

事实是槽位里的一句话；梦是另一种记忆——从一段对话里蒸馏出的散文：试过什么、哪里失败了、为什么、工作停在哪。它存在自己的表里，永不写事实，并且**默认关闭**。

一次整理怎么跑：

1. **采集。** 开启期间，每轮结束把这轮原文逐条追加到待整理区（`dream_feed`），同时记录每个会话的高水位；重启后从上次停下的位置继续，既不回采也不漏采。
2. **判决。** 素材值得才跑：未整理满 10,000 字符，或 3 个会话且满 2,000 字符，或单轮新增 6,000 字符，或闲置 7 天且满 2,000 字符的保底触发。阻尼优先：两次自动整理至少隔 6 小时，每个本地日历日最多 2 次。手动「现在整理」跳过阈值，但不跳过总开关。
3. **蒸馏。** 整会话打包进一个有界提示词（单次最多 40k 字符）；用户消息不足 3 条的会话留在待整理区等下次（全都太薄时放宽到 1 条，否则待整理区会一直亮着却永远凑不出素材）。疑似密钥或私密内容的行在进模型前整行丢弃。
4. **校验。** 回答在本地逐条检查：最多 5 条；主题键必须匹配 `[a-z0-9-]`；同一主题没有新素材时不得复述；至少一个来源真的出现在素材里；正文重复直接拒。带标识符但素材里找不到的保留，但标记 `unverified`。
5. **审阅。** 每条都先落 `pending`。采纳（或改写后采纳）才变 `active`；拒绝会记住主题，之后不再提。不点这一下，任何东西都进不了库，而且整理前后事实行数完全一致。

两层用「副本语义」隔开：梦不会被 `memory_search` 检索到，也不会被当成事实注入。`dreamInjectMode: "cue"` 时唯一对模型可见的只有一行「有这篇记录」并点出主题；`off` 连这一行都没有。

隐私：待整理区是对话的第二份拷贝，所以它只在开启时存在，未消费的素材超过 `dreamFeedRetentionDays`（30）天会被清理，被一次整理消费后即删除，一键清空也会一起清掉。

### 时间、热度与历史

一条记录带两只钟，和事实表同构。**事务时间**是 `created_at`/`updated_at`——我们什么时候读到的；**世界时间**是 `valid_from`/`valid_to`——它描述的事什么时候成立：`valid_from` 取这条记录覆盖的最早一条消息，采纳一条取代他人的记录时，旧记录的时间窗闭合在「新说法被说出的那一刻」。取代不删除，所以页签能直接读出时间线，而不是猜哪一版是当前。

**热度是量出来的，不是算出来的**：真实消息命中提示时 `hit_count` 加一，`last_hit_at` 记下时间。没有衰减系数——编一条曲线只会显得精确。热度只决定两件事：主题索引的排序，以及 `dreamArchiveAfterDays`（默认 90）之后的归档。归档是状态不是删除：记录、来源、时间线都在，提示与索引不再提供它，页签一键恢复。

**主题索引**在页签顶部，由规则从在用的记录生成（最多 20 行）：标题、主题键、命中次数、起始日期。它是「有什么」的地图，不是「讲了什么」的摘要。

**历史回填**只能手动触发。`POST /api/fact-memory/dream-backfill` 带 `{"backfill": true}` 时读取 `<DSH_HOME>/sessions` 下的会话归档（多帧 zstd，新的优先），用同一套密钥/隐私过滤，丢掉压缩摘要（摘要是摘要的摘要，不是谁说过的话）和宿主/插件注入的提示（每轮一条的事实记忆提醒、运行上下文快照、审批通知等，都不是用户说过的话），最多复制 `dreamBackfillMaxSessions`（50）个会话 / `dreamBackfillMaxChars`（200000）字符进待整理区。已经采集过的会话会跳过，重复执行不会重复入库；回填落库之后，仍由正常阈值决定何时整理。

**梦**页签显示待审、已采纳、以及「为什么下一次该跑 / 不该跑」的状态行，并提供一个可填写关注点的「现在整理」按钮。

## 本版本的边界

以下能力刻意不做，免得读者误会：

- 不内置也不推荐任何向量模型：向量与重排通道已经存在，但在你把它指向某个端点之前一直是关的，而且每次结果都会说明哪些通道真正跑过；
- 模型抽取默认关闭，而且始终只发文本：不给模型工具、不给会话历史、不给写库权限；低于置信线的值只会成为提案，绝不静默落库；引用对不上原文的候选一律丢弃；
- 不做批量维护工具：页面已经覆盖浏览、改值、失效、提案、冲突与一跳图谱，但没有多选批处理、没有跨实体重写，数据交换也仍只有事实 JSONL 这一种包；
- 不做跨设备同步；交换格式就是 JSONL 导出/导入；
- 导入不自动裁决冲突：进队列，等人点头；
- 不把图谱自动扩进提示词：图谱按需读取，绝不把邻居正文塞进上下文。
